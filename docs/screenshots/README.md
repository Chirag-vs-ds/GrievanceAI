# Screenshot Checklist

No application screenshots are currently stored here. Capture these views from `http://localhost:3000` after starting MySQL, FastAPI, and Next.js.

Use a clean browser window, fictional complaint text, and a test grievance ID. Crop out browser profiles, unrelated tabs, machine usernames, local paths, developer consoles, and notifications. Never capture passwords, `.env` contents, cookies, JWTs, API keys, database credentials, real Aadhaar numbers, biometrics, or real citizen information.

## Required screenshots

1. **Homepage** — show the hero, Submit and Track actions, and overall design. Save as `01-homepage.png`.
2. **Complaint submission form** — show the empty form, character guidance, and submit action. Save as `02-submission-form.png`.
3. **Successful submission** — use a clearly fictional complaint and show the grievance ID, category, department, priority, and review guidance. Save as `03-submission-success.png`.
4. **Tracking result** — track the same fictional grievance and show its stored status and details. Save as `04-tracking-result.png`.
5. **Admin login** — capture before entering credentials, with both fields empty. Save as `05-admin-login.png`.
6. **Admin dashboard** — show summary cards/charts and part of the fictional grievance table. Save as `06-admin-dashboard.png`.
7. **Status update** — show the fictional grievance and a completed transition or success message. Save as `07-status-update.png`.
8. **Activity Logs** — show the status event and filter/pagination controls. Use a non-sensitive demo admin username if it will be visible publicly. Save as `08-activity-logs.png`.
9. **Analytics** — show status totals and distribution charts populated only by fictional records. Save as `09-analytics.png`.

## Capture quality

- Use a consistent desktop viewport, preferably 1440×900 or similar.
- Save readable PNG files at normal browser zoom.
- Use the same fictional grievance across submission, tracking, status, and logs.
- Verify analytics counts agree with the demonstrated workflow.
- Review every image at full size before adding it to Git.
- Do not edit data into a screenshot or generate substitute screenshots.

After capture, add selected images and concise captions to the root README.
